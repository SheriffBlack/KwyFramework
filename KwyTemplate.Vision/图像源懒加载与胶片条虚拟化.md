# 图像源懒加载与胶片条虚拟化

## 背景

本地图像、文件夹、多图输入不能在节点执行时一次性把所有大图解码到 UI 像素缓存中。

以 `5472x3648` 的 `Bgra32` 图像为例，单张图约 80 MB，4 张图会超过 300 MB。如果图像面板、缩略图和缓存再各复制一份，很容易造成 GC 抖动、UI 卡顿和运行耗时异常。

因此图像输入和显示必须拆成两层：

- 图像源：描述图像来自哪里，以及如何按需读取。
- UI 显示：只为当前可见图像加载像素，只为胶片条加载缩略图。

## 设计目标

- 节点执行阶段只建立图像源和元数据，不主动全量解码所有像素。
- `VisionImageViewer` 只加载当前选中图像的全量像素。
- 胶片条只加载小缩略图，不触发全量大图像素复制。
- 多图列表使用虚拟化，避免一次性创建所有图片卡片。
- 图像源、Viewer、列表 VM 职责分离，避免 UI 层知道文件解码细节。
- 同一份图片格式、文件解析、缩略图规则只维护一处。

## 职责划分

| 类型 | 职责 |
| --- | --- |
| `Kwy.Vision.WPF.Images.VisionMediaFileTypes` | 本地媒体文件规则，集中维护图片/视频扩展名、文件对话框过滤器、目录展开和初始目录解析。 |
| `Kwy.Vision.WPF.Images.ILocalVisionImageFactory` | 本地图像源工厂，模板层通过接口创建图像集合，不直接依赖具体文件图像实现。 |
| `Kwy.Vision.WPF.Images.LocalFileVisionImage` | 本地文件图像源，实现 `IVisionImage`。构造时只读取尺寸、格式、时间等元数据；`GetPixelMemoryAsync` 被调用时才解码全量像素。 |
| `Kwy.Vision.WPF.Images.IVisionImageThumbnailProvider` | 可选缩略图能力。文件图像源可直接按小尺寸解码缩略图，避免为了胶片条读取完整大图。 |
| `Kwy.Vision.WPF.Images.VisionImageThumbnailFactory` | WPF 缩略图创建入口，封装像素格式到 WPF `ImageSource` 的转换。 |
| `VisionImagePanelItemViewModel` | 图像面板项。持有 `IVisionImage` 引用、序号、摘要、Overlay 信息；按需调用 `EnsurePixelsAsync` 获取当前图像像素；`ThumbnailSource` 懒创建并缓存。 |
| `VisionImageViewer` | 当前图像显示控件。切换选中图像时异步加载当前图像像素，加载完成后写入复用的 `WriteableBitmap`；负责缩放、平移、ROI、Overlay 和像素值读取。 |
| `FlowExecutionService` / `FlowExecutionContext` | 记录运行图像快照和多图序号，不负责 UI 像素复制。 |
| `VisionImageCache` | 只按已加载像素估算内存。未加载像素的图像项不计入大图内存成本。 |

## 执行流程

```text
选择文件/文件夹
  -> VisionMediaFileTypes 枚举图片路径
  -> VisionLocalImageInputExecutor 通过 ILocalVisionImageFactory 创建图像集合
  -> FlowExecutionContext 记录 FlowImageSnapshot
  -> VisionImagePanelItemViewModel 持有 IVisionImage 引用
  -> 胶片条绑定 ThumbnailSource 时只创建小缩略图
  -> VisionImageViewer 选中某张图时调用 EnsurePixelsAsync
  -> LocalFileVisionImage.GetPixelMemoryAsync 解码当前大图
  -> VisionImageViewer 写入 WriteableBitmap 并显示
```

## 胶片条虚拟化

图像结果胶片条是横向 `ListBox`，用于多图快速切换。它不是日志类列表，不应自动滚到底，也不应关闭虚拟化。

推荐配置：

```xml
<ListBox
    ScrollViewer.CanContentScroll="True"
    ScrollViewer.HorizontalScrollBarVisibility="Auto"
    ScrollViewer.VerticalScrollBarVisibility="Disabled"
    VirtualizingPanel.IsVirtualizing="True"
    VirtualizingPanel.ScrollUnit="Pixel"
    VirtualizingPanel.VirtualizationMode="Recycling">
    <ListBox.ItemsPanel>
        <ItemsPanelTemplate>
            <VirtualizingStackPanel Orientation="Horizontal" />
        </ItemsPanelTemplate>
    </ListBox.ItemsPanel>
</ListBox>
```

说明：

- `VirtualizingStackPanel` 只创建可见区域附近的卡片。
- `VirtualizationMode="Recycling"` 复用容器，减少频繁创建销毁。
- `ScrollUnit="Pixel"` 保留像素级滑动体验，允许卡片从中间截断显示。
- 不要使用 `ScrollViewer.CanContentScroll="False"`，否则会关闭基于 item 的虚拟化能力。

## UI 展示约定

- 主图信息显示在 `VisionImageViewer` 内部，例如节点名、端口、当前序号 `2/5`、尺寸、像素格式、Overlay 数量。
- 胶片条卡片只显示真实缩略图和序号角标，不重复显示完整图像信息。
- 单图时隐藏胶片条，把空间留给主图。
- 多图时胶片条仅用于切换当前图像。
- ROI 列表和图像胶片条是两类不同面板：ROI 列表服务区域编辑，胶片条服务多图浏览。

## 性能约束

- 不要在 `VisionImagePanelItemViewModel.CreateAsync` 中调用 `IVisionImage.GetPixelMemoryAsync`，否则会回到创建列表项时全量复制大图的旧问题。
- 不要为了缩略图读取完整大图；优先让图像源实现 `IVisionImageThumbnailProvider`。
- 不要让 XAML 或 Viewer 直接知道本地文件路径解码规则；本地文件细节应收敛在图像源服务中。
- `VisionImageViewer` 可以持有当前显示图的像素缓存，但不应主动加载所有图像。
- 若后续接入相机、Buffer、OpenCV、HALCON 图像源，应优先实现统一的 `IVisionImage`，必要时再补充缩略图提供能力。

## 后续方向

- 为 `IVisionImage` 增加更通用的预览/缩略图抽象，而不是只依赖本地文件实现。
- 为大图像素缓存增加内存上限和淘汰策略。
- 对批量运行和 UI 预览区分不同加载策略：批量运行关注吞吐，UI 预览关注当前帧响应。
- 视频输入接入后复用同样模式：视频源只暴露帧索引和缩略图，当前帧被选中时才解码完整帧。
