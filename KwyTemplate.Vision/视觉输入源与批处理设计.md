# 视觉输入源与批处理设计

## 目标

视觉平台中的本地图像、本地视频和相机采集都属于“图像帧源”。节点执行器不应该直接关心文件枚举、视频解码或相机 SDK，而是统一从帧源中读取一帧或一组帧。

这样可以保持：

- 高内聚：文件规则、帧枚举、图像创建集中在 `Kwy.Vision.WPF`。
- 低耦合：`KwyTemplate.Vision` 执行器只依赖 `IVisionFrameSourceFactory`。
- 可扩展：后续接入 OpenCV、DirectShow、海康、基恩士等 SDK 时替换帧源实现，不重写流程执行逻辑。

## 核心类型

| 类型 | 职责 |
| --- | --- |
| `IVisionFrameSource` | 统一的帧源接口，提供 `ReadFrameAsync` 和 `ReadAllFramesAsync`。 |
| `VisionFrame` | 单帧数据，包含 `IVisionImage`、源名称、序号和总数。 |
| `IVisionFrameSourceFactory` | 创建本地图像、本地视频、相机帧源。 |
| `LocalImageFrameSource` | 本地图像帧源，支持单图、多图和文件夹。 |
| `PlaceholderVisionFrameSource` | 视频/相机的占位帧源，先统一接口，后续替换为真实实现。 |
| `VisionFrameSourceFactory` | 默认帧源工厂。 |

## 执行链路

```text
本地图像节点参数
  -> IVisionFrameSourceFactory.CreateLocalImageSource
  -> LocalImageFrameSource
  -> VisionFrame
  -> VisionLocalImageInputExecutor 输出 Image / ImageList
```

批处理运行时：

```text
当前流程
  -> 找到本地图像节点
  -> 枚举 LocalImageFrameSource 的所有 VisionFrame
  -> 每次把当前帧注入 FlowExecutionContext.Items
  -> 下游节点仍然消费单张 Image
  -> BatchRunRecords 记录 OK/NG、耗时、图片名
```

这避免了把 `ImageList` 直接连给 YOLO 这类单图算法节点。

## 视频和相机后续接入

视频帧源建议实现：

- 按帧号读取。
- 按时间戳读取。
- 顺序读取下一帧。
- 支持文件夹多视频批量验证。
- 仅在读取当前帧时解码，不把整段视频一次性转成图像列表。

相机帧源建议实现：

- 本机摄像头和工业相机统一为 `IVisionFrameSource`。
- 触发模式、曝光、增益作为 `VisionCameraSourceOptions`。
- SDK 相关对象封装在帧源实现内，不泄漏到流程节点和 UI。
- 后续可增加设备枚举服务，属性面板从服务获取相机列表。

## 注意

`ILocalVisionImageFactory` 已改为复用 `LocalImageFrameSource`，保留它只是为了兼容旧代码。新增逻辑应优先使用 `IVisionFrameSourceFactory`。
