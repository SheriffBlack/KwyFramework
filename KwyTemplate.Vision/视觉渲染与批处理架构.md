# KwyTemplate.Vision 渲染与批处理架构

## 设计目标

`KwyTemplate.Vision` 是视觉平台应用模块，不直接绑定 HALCON、OpenCV 或某个相机 SDK。

图像显示和图像处理按场景拆分：

- `VisionImageViewer`：流程结果预览、节点调试、ROI 编辑、Overlay 显示。
- `VisionLiveImageViewer`：相机实时流显示，只显示最新帧，不保存历史图。
- `HalconSmartWindowImageViewer`：HALCON `HImage` 高频原生显示，放在 `Kwy.Vision.Halcon.WPF`。
- `VisionBatchProcessor`：离线批量跑图、文件回放、算法批处理。
- `VisionImageCache`：结果图或离线图像的 LRU 缓存。

## 分层关系

```text
Kwy.Vision.Abstractions
  图像、几何、算法请求/结果等公共契约

Kwy.Vision.Halcon
  HALCON 算法和 HImage 包装

Kwy.Vision.Halcon.WPF
  HALCON WPF 原生显示控件适配

KwyTemplate.Vision
  视觉平台界面、流程编辑、结果显示、实时流显示和批处理编排
```

`KwyTemplate.Vision` 可以消费 `Kwy.Vision.Abstractions`，但不应该直接把平台页面写死到 HALCON 控件上。
需要 HALCON 高频显示时，由业务项目显式引用 `Kwy.Vision.Halcon.WPF`。

## 结果预览

`VisionImageViewer` 用于流程结果图：

- 支持缩放、平移、ROI 编辑。
- 支持 Overlay 绘制。
- 内部使用 `WriteableBitmap.WritePixels` 复用显示缓冲。
- 适合节点输入图、输出图和调试结果。

它不适合承担 100 FPS 以上的相机实时流播放。

## 实时流显示

`VisionLiveImageViewer` 和 `VisionLiveImageRenderer` 用于相机实时流：

- 只创建一次 `WriteableBitmap`。
- 使用 `Lock`、`BackBuffer`、`AddDirtyRect`、`Unlock` 更新图像。
- 使用 `isRendering` 防止高频帧重叠。
- UI 正忙时允许丢帧，只保留最新视觉反馈。

这种方式适合普通 byte[]、相机帧缓冲或 OpenCV 导出的连续像素内存。

## HALCON 高频显示

HALCON `HImage` 高频显示不建议走：

```text
HImage -> byte[] -> WriteableBitmap
```

这会引入大块内存复制和 GC 压力。

推荐使用：

```text
HalconVisionImage -> HSmartWindowControlWPF
```

对应实现放在 `Kwy.Vision.Halcon.WPF`，避免污染 `Kwy.Vision.Halcon` 算法层。

## 批处理

`VisionBatchProcessor` 用于离线批量跑图：

- 使用 `System.Threading.Channels` 做背压。
- 支持多 worker 并发处理。
- 支持取消、停止、完成统计。
- 具体算法逻辑通过委托注入，避免与流程节点强耦合。

后续如果需要“文件夹批量回放”“算法压测”“离线评估”，应扩展这个模块，而不是塞进 `FlowExecutionService`。

### Batch 模块组成

```text
Batch
├── VisionBatchProcessor
├── VisionBatchItem
└── VisionBatchItemStatus
```

`VisionBatchItem` 表示一张待处理图或一个待处理任务：

| 属性 | 说明 |
| --- | --- |
| `Source` | 文件路径或数据源标识。 |
| `Status` | 当前处理状态。 |
| `ElapsedMilliseconds` | 单项处理耗时。 |
| `ErrorMessage` | 失败原因。 |
| `Result` | 算法结果。 |

`VisionBatchItemStatus` 表示批处理状态：

```text
Pending
Loading
Processing
Completed
Failed
Canceled
```

`VisionBatchProcessor` 是批处理调度器，负责：

- 接收一批 `source`。
- 创建有界 `Channel` 队列。
- 启动多个 worker 并发处理。
- 在队列满时形成背压。
- 支持停止和取消。
- 统计完成数量和失败数量。
- 通过 `ItemCompleted` 事件反馈单项结果。

### Batch 使用示例

```csharp
var processor = new VisionBatchProcessor(async (item, token) =>
{
    // item.Source 可以是文件路径、图片编号或业务数据源标识。
    // 这里编排图像读取、算法执行和结果返回。
    await Task.Delay(10, token);
    return "OK";
});

processor.ItemCompleted += (_, item) =>
{
    Console.WriteLine($"{item.Source}: {item.Status}, {item.ElapsedMilliseconds} ms");
};

await processor.StartAsync(files);
```

### 适用场景

`Batch` 适合：

- 选择一个文件夹，批量跑全部图片。
- 算法开发时压测大量样本。
- 离线回放相机历史图。
- 统计 OK/NG、耗时和失败原因。
- 批量验证参数稳定性。

`Batch` 不适合：

- 相机实时预览。
- 单次在线流程运行。
- PLC 触发一次拍照检测。
- 节点结果图显示。

这些场景应继续使用：

```text
FlowExecutionService
VisionImageViewer
VisionLiveImageViewer
```

### 为什么不放进 FlowExecutionService

在线流程和离线批处理的目标不同：

| 类型 | 关注点 |
| --- | --- |
| 在线流程 | 低延迟、节点状态、当前流程调试、和 UI 交互联动。 |
| 离线批处理 | 吞吐量、队列、背压、并发、统计、可取消。 |

因此批处理独立为 `Batch` 模块，避免 `FlowExecutionService` 同时承担在线运行、批量文件、实时流和统计任务，形成过重服务。

## 缓存

`VisionImageCache` 是 LRU 缓存：

- 按数量限制。
- 按估算像素内存限制。
- 用于结果图、离线图、回放图缓存。

实时流不要进入缓存。实时流只显示最新帧。

## 使用建议

| 场景 | 推荐组件 |
| --- | --- |
| 节点结果图 | `VisionImageViewer` |
| ROI/Overlay 调试 | `VisionImageViewer` |
| 相机实时画面 | `VisionLiveImageViewer` |
| HALCON HImage 高频显示 | `HalconSmartWindowImageViewer` |
| 文件夹批量跑图 | `VisionBatchProcessor` |
| 结果图缓存 | `VisionImageCache` |

核心原则：

```text
结果预览和实时流分开。
平台界面和厂商显示分开。
在线流程和离线批处理分开。
```
